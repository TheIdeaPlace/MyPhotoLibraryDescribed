# My Photo Library Described for Windows

A Windows app for browsing your photos and videos as if they were folders in File Explorer, built to work well with JAWS, NVDA and Narrator. It's the Windows counterpart of the Mac app in this repository and does the same job: a sidebar and a sortable list replace the Photos app's image grid.

On Windows your photo library is ordinary files, so My Photo Library Described reads the **Pictures library** (the same folders the Photos app and File Explorer show), plus any folders you add.

## What it does

- **Sidebar** with *Library* (All Photos, Favorites, Recently Added, Videos, Screenshots, Screen Recordings, Panoramas, RAW and Animated), *Dates* (a folder for each year, with a folder for each month inside) and *Folders* (the library's folders on disk, with their subfolders).
- **List view** with Name, Date Taken, Kind, Caption, Dimensions, Duration and Favorite columns. Click a column header, or use View > Sort By, to sort. **View > Labels…** (it was Columns; or right-click a column header) has two tabs (#38). **List** picks which columns are shown and in what order; **Gallery** picks what's said, in order, when you move to a photo in the gallery: Position ("12 of 400", the default), Name, Kind, Date Taken, Dimensions, Caption, Keywords, Rating and Place Taken, with the description following after the usual pause. Each tab has Available and Shown lists, Add, Remove, Move Up, Move Down, Move to Top, Move to Bottom and Reset to Default, with a preview of how the selected photo will read. In it, Alt+Up, Alt+Down, Alt+Home and Alt+End move the selected column, Enter in Available adds one and Delete in Shown removes one, and each change is spoken. The order is also the order screen readers read each row in, so putting Caption or Date Taken first means hearing it before the file name. Name is always shown, but can be moved. The extra columns are Keywords, Rating, Date Modified, File Type, Size, Orientation, Megapixels, Place Taken (where the photo was taken) and Folder (where the file is).
- **Gallery view** (View > as Gallery) shows one full-size image at a time. The image is named with just the file name, so arrowing says which photo and its description follows, and a screen reader's image description (JAWS Picture Smart, NVDA's describers) looks at the whole picture instead of a thumbnail. Arrow keys move between items. Tab from the photo goes through the footer: the name, details, caption and description, then Previous, the position ("3 of 10") and Next.
- **Read-only until you say otherwise (#83).** My Photo Library Described starts read-only, and nothing changes a photo file: no captions, alt text, ratings or Favorites, and Save Descriptions in Photos is paused (it reads as unchecked, "Save Descriptions in Photos (Paused in Read-Only Mode)"; descriptions made meanwhile aren't saved into photos later). Reading photos to describe them is all it does, and descriptions are kept in My Photo Library Described's own files. File > Read-Only Mode turns it off after asking every time, with the risk said plainly and Keep Read-Only Mode as the default button. Allowing changes lasts until My Photo Library Described quits: every launch starts read-only. The title bar ends with "Read-Only Mode" or "Editing Mode" ("Mode", so a screen reader doesn't sound as if a control is read-only). A command that would change a photo says why it can't while read-only. The writers themselves refuse too, so nothing gets past it.
- **Status bar**: the last stop in the F6 loop, as in QuickMail. F6 there says "Status bar" and what it shows; Left and Right Arrow move between its sections (the library summary, what's being done now, and background describing), and Tab, F6 or Escape leave. Ctrl+F9 speaks it without moving focus, from the main window, Preview or Get Info (View > Read Status Bar), and Ctrl+Shift+F9 goes to it (View > Go to Status Bar). JAWS (Insert+Page Down) and NVDA (Insert+End) read it too.
- **Preview** (Space) is My Photo Library Described's Quick Look: a large view of the photo, or the video playing, with the arrow keys moving through the list. Space or Escape closes it.
- **Edit Caption** (F2) writes the caption into the file, in the standard caption field for JPEG, PNG, TIFF and HEIC and as the Title File Explorer shows for others, so it goes wherever the file goes (and syncs with OneDrive).
- **Descriptions in photos:** Photo > Use Description as Caption (also in the list's context menu and in Get Info) writes each selected photo's saved description into its caption, and into a JPEG, PNG, TIFF or HEIC file's accessibility fields (IPTC Alt Text, with the Extended Description when the alt text had to be shortened to 250 characters), asking before replacing what's there. **Photo > Save Descriptions in Photos** (off until you agree, once) does the same quietly whenever a description is saved, but only fills empty captions and alt text: never what you or another app wrote. Your earlier Save Descriptions as Captions choice carries over. In JPEG, PNG, TIFF and HEIC files the caption is the standard XMP Caption/Description (`dc:description`), with Explorer's Title kept in step when it's empty or held the old caption; other formats keep the caption in the Title. JPEGs are changed segment by segment (#86): only the XMP metadata is replaced, so the EXIF block (with its thumbnail and the camera's MakerNote), comments, the picture and anything after it, such as a motion photo's video, stay byte for byte (except EXIF's own title, emptied in place when it held the old caption); ratings go in the XMP too, with EXIF's own rating patched in place. Multi-picture files (Ultra HDR, Apple's HDR photos, MPO) are captioned too (#90): their index of pictures is updated for the larger header, and the gain map or other view stays byte for byte; Pixel photos whose XMP continues in Extended XMP segments are captioned too (#149), with the main XMP replaced and every extension segment kept byte for byte, after checking the parts add up to the packet the main XMP names (and that what would change isn't in the extension); one whose index can't be followed is changed only when that keeps its size, and otherwise the reason is said. A JPEG whose Photoshop IPTC was changed after its digest was written holds an older caption that other apps would show instead, so its caption isn't changed, and the reason is said (#169). PNGs are changed chunk by chunk the same way (#82): only the XMP chunk is replaced, and anything My Photo Library Described can't follow, such as a damaged chunk, is left alone with a reason. TIFFs go through WIC, never decoding the picture. Either way the new file is written beside the photo and swapped in whole, so a failure partway leaves the photo as it was. The automatic saving also leaves an extended description another app wrote alone. Get Info shows any alt text in the file.
- **Favorites** are photos rated five stars, so they're the same in File Explorer and other apps that read ratings. Photo > Rating sets any rating.
- **Get Info** shows the date, location coordinates, camera, lens and exposure details. With **Photo > Look Up Place Names** on, it also names the place a photo was taken ("85 Pike Street, Seattle, Washington, United States"), above the coordinates. That sends the coordinates, and the language Windows uses so the name comes back in it, to OpenStreetMap's Nominatim when Get Info opens (nothing about you or the photo), so it's off until you turn it on, and it asks first (#25). At most one request a second, never in the background, and names found are kept in the data folder (PlaceNames.json), so the same spot is sent once. Each name is credited "(© OpenStreetMap contributors)", as the data's licence asks. If Nominatim refuses (too many requests), nothing more is asked until My Photo Library Described starts again. And it can be switched off for everyone without an update, as Nominatim's policy asks (#128): before a lookup, at most once a day, the app reads `config/services.json` from this repository; with `placeNames.windows.enabled` false, nothing goes to Nominatim and Get Info shows the file's `message` (or "Place names are paused for now.") where the name would be. Names already found still show. If the file can't be read, the last copy read stands, and with none, lookups are on. Its *Image Contents* section has:
  - **Describe Image**, which describes the photo with Windows' on-device AI on Copilot+ PCs (`Microsoft.Windows.AI.Imaging`). Choose Accessible, Detailed, Brief or Diagram descriptions. The photo isn't sent anywhere.
  - **Read Text in Image**, which reads any text in the photo with Windows' built-in text recognition, on any Windows 10 or 11 PC.
- **Describe Photo** (Ctrl+D): describes the photo you're on, in the list, the gallery or Preview, and speaks the description where you are, whether or not automatic descriptions are on. A saved description is spoken at once; **Redescribe** (Ctrl+R) describes it afresh and replaces the saved one, and Get Info's button says Redescribe when there's a saved description. **Go > Go to Description or Back to Photos** (Ctrl+Shift+D) goes to the Description panel's text box, showing the panel if it's hidden; pressed there, it goes back to the list or gallery. Photo > Description Type chooses Accessible, Detailed, Brief or Diagram for this and for automatic descriptions (Get Info's choice changes it too).
- **Automatic descriptions**: on a Copilot+ PC, arrow to a photo and pause, and My Photo Library Described describes it with Windows AI and speaks the description as a UIA notification, so JAWS, NVDA and Narrator read it without moving focus. It waits for the row's name to be read first, then queues behind it rather than cutting it off; moving on silences it. Descriptions are saved, so going back to a photo speaks after the same short pause, and arrowing quickly past photos only describes the one you stop on. Stepping through photos one at a time, the next photo in the direction you're going is described quietly while you listen to this one, so it's ready when you get there; not on energy saver, and only when Windows AI is ready. Like any new description, it's also saved in that photo when you've chosen to save descriptions in photos. Descriptions are only made and spoken while you're in the list or gallery, not the sidebar, search or a dialog. They also show in the gallery and in Get Info. It uses Photo > Description Type; Brief keeps it short. Photo > Describe Photos Automatically (Ctrl+Shift+U) turns it on and off. On a PC without Windows AI it stays quiet; turning it on says why, and gets Windows' model ready if it only needs downloading.
- **Background descriptions**: with Photo > Describe Photos in the Background turned on, the library's photos that haven't been described yet are described behind the scenes, newest first, one at a time: when it's turned on, each time My Photo Library Described starts (so a big library, a network share included, carries on across restarts), and for a folder as it's added (#96). They're described so their descriptions are ready when you get to them: spoken after the usual short pause, without waiting for Windows AI. The status bar shows "Describing photos in the background, X of Y" (Ctrl+F9 reads it), and you hear when an added folder is finished. A folder you add goes ahead of the library's backlog. It waits on energy saver (the status bar says so), and if several photos in a row can't be described (a missing HEIF codec, say) it stops and says why rather than failing through the rest. Photos Windows' content filter declines, or that have too much text to describe, don't count towards that, since that's a verdict on the photo, not a sign describing doesn't work. A photo that couldn't be described isn't tried again at the next start either (it's remembered in the data folder's BackgroundFailures.json), so the same few at the front of the queue can't stop every run; other failures are remembered only once a later photo was described, so a run that stops (a missing codec, say) leaves nothing skipped once it's fixed. Turning Describe Photos in the Background off and on tries them all again, as does an update; an edited photo is tried again too, and Describe Photo always tries. Photo > Stop Background Describing stops this run (the setting stays on, and the next start carries on); arrowing to a photo always comes first. Photos already described, videos and online-only cloud photos are skipped. It's off until you turn it on; turning it on says if Windows AI isn't available, and gets the model ready if it only needs downloading. At a start, if Windows' model needs getting ready again (after a Windows update, say), it does that itself, and the status bar says so. If Windows AI doesn't answer (it can be slow just after signing in), the status bar says it's waiting, and it asks again soon and then every ten minutes; the first description that works anywhere (Describe Photo, say) starts it at once. Help > Open Log Folder has the details.
- **Open, Copy, Export, Show in File Explorer and drag** work on the files themselves. Export never overwrites: a second copy of `IMG_1.JPG` becomes `IMG_1 2.JPG`.
- Folders, years and months also appear as rows in the list, so you can move through the library like File Explorer.
- **Description panel** (View > Show Description, Ctrl+Shift+I, on by default): beside the list or gallery, the photo you're on (in list view, with a picture of it at the top, which screen readers skip and which never downloads an online-only file) with its description in a box you can read by line, word or character and correct (Enter saves; Shift+Enter starts a new line), marked "Edited by you" so nothing replaces it without asking. A status line says "Describing…", "Saved description", "Edited by you" or "Not described yet", with Redescribe, Use as Caption and Copy, and the caption with Edit Caption. It's in the F6 cycle after the list or gallery, and its width can be dragged. View > Labels (List tab) also has a **Description** column, off by default, which is read with the row when shown.
- **Help** has Check for Updates…, Report a Bug…, Check System…, Check AI Description…, Open Log Folder and About. **Check System** lists, one line each, whether the PC can describe photos (each OK or what to do: the Windows build, the NPU, Windows AI and the library folders), with Check Again, Copy to Clipboard and Report a Bug, then the details behind the AI, for bug reports and for checking your own setup: Windows' edition, the processor, memory and power, the NPU and its driver, the AI helper's version, the Windows App Runtime and the Windows AI packages, text recognition's and Phi Silica's states, how long this session's descriptions took, and the last few failures. **Check AI Description** describes a sample picture that comes with the app (a red mug on a wooden table beside a sign reading OPEN), to show describing works end to end apart from your own photos: it shows the description, how long it took, and whether it mentions what the sample shows. It changes and saves nothing, and its result appears in Check System and in bug reports. **Open Log Folder** shows My Photo Library Described's diagnostic log in File Explorer: one file a day, kept for two weeks, recording what it started with and what went wrong (the AI helper, describing, background describing, saving, crashes), for attaching to a bug report. It stays on the PC unless you send it; your Windows user folder is written as %USERPROFILE%, but it does name files and folders, so look before attaching it to a public issue. The update item always says what's running, "Check for Updates (running 0.1.0)…", and becomes "Update to 0.2.0 available…" when a quiet check (a few seconds after starting, at most once a day) finds one. The first launch after an update says "My Photo Library Described Update Installed", with See What's New for the release notes; Enter or Escape closes it. **Report a Bug** opens a form (#138), as on the Mac: Bug or Suggestion, a title, what happened, what you expected and the steps (or the suggestion), an optional contact, "Include the system check", and a preview of exactly what's sent. Send files it as a GitHub issue through The Idea Place's bug-report relay and says "Report filed as issue #N", with Open Issue. Without the relay key (only release builds have it: `build-msix.ps1` copies `~/.signing-kit/appkit-relay-photofinder.key`, or the `APPKIT_RELAY_KEY` secret in CI, into the package as `appkit-relay.key`), or when the relay fails, it copies the report and offers Open in Browser, the prefilled GitHub page. If the app didn't quit cleanly last time, it asks once at the next start whether to report it, with the end of the log attached. **About** has the version and links to the source code, the user guide and the privacy policy.
- Screen readers hear the results of navigation, sorting, exports, copies and favorite changes.

## Describe Image and the AI helper

Windows only lets a *packaged* app use its image description model, so the describing is done by **My Photo Library Described AI helper** (`src/PhotoFinderAI`), a small packaged console program that My Photo Library Described starts through the command its package adds, `photofinder-ai`. It's adapted from the helper in [Image Description Toolkit](https://github.com/kellylford/Image-Description-Toolkit) and speaks the same JSON-lines protocol.

It needs:

- A Copilot+ PC (with an NPU) and a recent Windows 11.
- The Windows App Runtime 1.8.
- The helper, which the installer puts in My Photo Library Described's own package. For development, in Developer Mode: `scripts\build-ai-helper.ps1 -Register`, then `photofinder-ai --check` should report `"state":"Ready"`.

Without the helper, Get Info says why Describe Image isn't available, and everything else, Read Text included, works as usual.

The first description after the model loads can take up to half a minute; later ones take a few seconds.

## Building

Requires the .NET 10 SDK on Windows.

```powershell
cd windows
dotnet build PhotoFinder.sln
dotnet run --project src\PhotoFinder
dotnet test --solution PhotoFinder.sln
```

Run the tests from PowerShell or cmd, not Git Bash: started from Git Bash, the AI helper answers every picture with an internal error (found in Image Description Toolkit; the cause isn't known). The Describe Image tests run only where the helper is installed and Windows' model is ready, and report themselves skipped everywhere else.

## Installing

My Photo Library Described installs as an MSIX package, Windows' own app format. Open **PhotoFinder.appinstaller** and Windows' App Installer shows My Photo Library Described with an Install button. It installs the Windows App Runtime first if the PC needs it, then My Photo Library Described for the PC's architecture (x64 or Arm64). My Photo Library Described is then in the Start menu, uninstalls from Settings > Apps like any app, and updates itself: Windows checks every few hours and installs a new build while My Photo Library Described isn't running, and Help > Check for Updates checks now. No admin rights or Developer Mode are needed, and the AI helper is part of the same package, so Describe Photo works on a Copilot+ PC straight away.

To build it:

```powershell
cd windows
.\scripts\build-msix.ps1 -Sign -Destination <folder> [-BaseUri https://...] [-Flat]
```

This writes `PhotoFinder.appinstaller`, `PhotoFinder_<version>.msixbundle` (x64 and Arm64) and `Dependencies\Microsoft.WindowsAppRuntime.1.8_<arch>.msix` (Microsoft's own, from the Windows App SDK). `-BaseUri` is where those files will be downloaded from and where updates are looked for. By default it's the destination folder itself, written into the .appinstaller as that exact path, so it works only on PCs where the same path exists (a OneDrive folder on your own PCs); to share My Photo Library Described with other people, give it an https address. `-Flat` puts the runtime packages beside the bundle rather than in `Dependencies\`, as a GitHub release needs. `-Sign` signs the executables and the bundle with Kelly Ford's Azure Artifact Signing certificate (`scripts\sign-files.ps1`; it needs `az login` and the Artifact Signing client tools), which every Windows PC trusts. Windows won't install an unsigned package, so Windows CI builds one unsigned only to check the packaging. Releases are built and signed by `.github/workflows/release.yml` when a `v<version>` tag is pushed (see CLAUDE.md, Releasing), with `-Flat -BaseUri https://github.com/TheIdeaPlace/MyPhotoLibraryDescribed/releases/latest/download`. The version is `windows\VERSION` plus a fourth number from the git history (ten times the commit count, plus 1 to 9 for a build with uncommitted changes), so builds of main made here and by a workflow agree and count up. Testers should get builds of main.

The package is laid out from `packaging\AppxManifest.xml` and `packaging\Assets` (the logos, drawn to match `src\PhotoFinder\PhotoFinder.ico`). The .appinstaller doesn't ask Windows to check for updates at every launch: that check stopped the helper's `photofinder-ai.exe` alias from starting. The installed app starts the helper from its own package folder instead of through the alias, so an older test install's helper or a development registration can't stand in for it.

If you used the earlier test installer (Install.cmd), remove it once, from PowerShell: `Get-AppxPackage TheIdeaPlace.PhotoFinder.WindowsAI | Remove-AppxPackage`, then delete `%LOCALAPPDATA%\Programs\Photo Finder` and the Photo Finder shortcut (its old name) in the Start menu's Programs folder. Your settings and descriptions in `%LOCALAPPDATA%\PhotoFinder` are kept and used by the installed app.

## Notes

- Online-only OneDrive files keep their file dates in the list: reading their details would download them. Opening, previewing or Get Info downloads that one file; its details fill in the next time the library is refreshed (F5). Changing many files, or any online-only ones, asks first.
- Captions and ratings go into the file itself: JPEG, PNG and HEIC by editing only their XMP (an iPhone HEIC gets an XMP item for the photo, the gain map's own XMP left alone), TIFF through WIC, and other formats (MP4 and MOV were tested) through Windows' property handlers. My Photo Library Described reads each change back and says which files it couldn't change, rather than claiming a save that didn't happen.
- Writing a caption or rating keeps the file's modified date, so a photo without a Date Taken doesn't jump to today.
- Photo details are saved to `%LOCALAPPDATA%\PhotoFinder` after the first read, so the library opens with its details already filled in. Settings and saved descriptions are kept there too. On a PC that didn't have that folder before, Windows keeps it inside My Photo Library Described's package data instead, and removes it when My Photo Library Described is uninstalled, saved descriptions included.
- People and Windows Photos albums aren't available: Windows doesn't offer them to other apps.

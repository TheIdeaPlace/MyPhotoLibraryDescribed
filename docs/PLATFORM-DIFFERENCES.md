# Mac and Windows: what's different

Photo Finder has two separate apps: the Mac app (`PhotoFinder/`, SwiftUI and PhotoKit) and the Windows app (`windows/`, WPF). They aim at the same job, browsing photos like folders with a screen reader, but each is built on what its platform offers. This is the list of where they differ, so gaps can be closed on purpose. Update it when either app changes.

## Differences that come from the platform

These follow from what each operating system offers apps, and aren't gaps to close.

| | Mac | Windows |
|---|---|---|
| What's browsed | The Photos library, through PhotoKit, and any folders added, as files on disk | The Pictures library and any folders added, as files on disk |
| Albums | My Albums, album folders and Shared Albums from Photos | No albums: Windows doesn't offer the Photos app's albums to other apps. The Folders section (the folders on disk, with subfolders) takes their place. |
| Smart albums | Photos' own: Favorites, Recently Added, Videos, Live Photos, Screenshots, Selfies, Portrait, Panoramas, Bursts, Slo-mo, Time-lapse, Cinematic, Long Exposure, Animated, RAW | Worked out from the files: Favorites, Recently Added, Videos, Screenshots, Screen Recordings, Panoramas (by shape), RAW, Animated |
| Kinds | Live Photo, Portrait Photo, Burst Photo, HDR Photo, Slo-mo Video, Time-lapse Video, Cinematic Video and the rest, from Photos | Photo, Screenshot, RAW Photo, Animated Image, Panorama, Video, Screen Recording |
| Favorites | Photos' Favorite flag, synced with iCloud Photos | A five-star rating in the file, so it's the same in File Explorer |
| Captions | Photos' caption (macOS 27 and later), synced with iCloud Photos. Files in added folders: the file's XMP description (`dc:description`, which ImageIO also copies to the IPTC caption), the field Photos, Preview and Spotlight read | JPEG, PNG and TIFF: the XMP description (`dc:description`), with Explorer's Title kept in step when it's empty or held the old caption. Other formats: the file's Title, the one File Explorer shows |
| Ratings | Shown, and set from Photo > Rating (macOS 27); files in added folders not yet | Shown, and set from Photo > Rating |
| Keywords | Shown (macOS 27 and later) | Shown, from the file's Tags |
| Files in the cloud | Downloaded from iCloud when opened, previewed or exported | OneDrive online-only files keep their file dates until refreshed after opening, because reading their details would download them |
| Opening and previewing | Exports the current version (with edits) to a temporary file, then opens it or shows it in Quick Look. Files in added folders open as they are. | Opens the original file. Preview (Space) is Photo Finder's own window, which plays videos too. |
| Copy, Export, drag | Exports the current version, downloading it if needed. Files in added folders are copied as they are. | Copies the original file |
| Image description | Apple Intelligence (macOS 27), in the app | Windows AI on Copilot+ PCs, through a small packaged helper, because Windows only lets packaged apps use the model |
| Reading text in photos | Vision | Windows OCR |
| Place Taken | Coordinates, plus a place name from Apple's reverse geocoding once Settings > Look Up Place Names is on (off until the person agrees, since it sends the coordinates to Apple; #105) | Coordinates only for now. Place names (#25) will come from OpenStreetMap's Nominatim (Kelly, 13 Oct): free with no key, opt-in in the same way, at most one request a second with an identifying User-Agent, and cached on disk, as IDT does. Windows' own geocoder needs an Azure Maps account and key, with billing |
| Library changes | PhotoKit's change observer. For added folders, the folder showing is watched for files added, removed or renamed, and View > Refresh (Command-R) reads them all again. | Watching the library's folders on disk, and Refresh (F5) |
| Screen reader announcements | VoiceOver announcements | UIA notification events, for JAWS, NVDA and Narrator |
| Columns from the source | Source (My Library, Shared Album, Synced; the folder's name for files in added folders) | Size and Folder |
| Unavailable menu items | macOS menus already let VoiceOver reach them | WPF skips disabled items, so Photo Finder's menu items stay reachable and are read as unavailable |
| Show the file | Not applicable | Show in File Explorer (Ctrl+Shift+R) |

## Gaps to close

Each gap below has a GitHub issue with the `parity` label (`gh issue list --label parity`). Claim and coordinate there, as `CLAUDE.md` describes. When a gap is closed, move it to "Now the same on both" in the same PR.

### On the Mac, from Windows

- **Moving between panes.** Both have F6 and Shift+F6 (Go > Next Pane and Previous Pane on the Mac) for the sidebar, the list or gallery, search and the status bar, with Left and Right Arrow between status bar sections. On Windows the status bar is reached only with F6, not Tab, as in QuickMail; on the Mac, SwiftUI's focusable status sections may also be Tab stops.
- **Tests.** Windows has about 270 tests; the Mac has a handful (columns and the description cache). Mac CI can't compile the macOS 27 code until GitHub's runners have Xcode 27.
- **Favorites and ratings in files in added folders.** Windows sets favorites (a five-star rating) and ratings in the files themselves. On the Mac, Toggle Favorite says it isn't available for files yet. Captions are written into files on the Mac too (#31).
- **Folders without Photos access.** The Mac shows nothing until Photos access is given, so added folders can't be browsed without it. Windows has no such permission.

### On Windows, from the Mac

- **Next and previous photo from anywhere.** The Mac's Go > Next Photo (Command-Right Arrow) and Previous Photo (Command-Left) step through photos in the list or gallery without moving focus, so you can stay in the Description panel (reading with a braille display, say) and step from photo to photo (Kelly, 13 Oct). Windows: to match, with keys of its choosing.

- **Follow-up questions about a photo.** The Mac's Apple Intelligence answers follow-up questions after describing. Windows' image description model takes no questions; Phi Silica (a Windows text model) could answer from the description, but is a separate piece of work.
- **What's in the photo.** The Mac's Find Objects and Text lists objects and scenes (Vision's classifier) as well as reading text. Windows reads text only: Windows has no built-in classifier for apps.
- **Place names.** The Mac shows the place name for a photo's location. Windows shows coordinates.
- **Accessibility fields in files (#31).** The Mac writes IPTC's Alt Text (Accessibility) and Extended Description (Accessibility) into JPEG, PNG, TIFF and HEIC files in added folders: alongside the caption, with Use Description as Caption (and the panel's Use as Caption) and with Save Descriptions in Photos (which only fills empty alt text). The alt text is the description when it's 250 characters or less, otherwise the whole sentences that fit; the extended description is the whole description, only when the alt text is shorter. PNG files are written by editing their chunks (#61): only the XMP changes, plus, when the caption changes, the EXIF description every screenshot carries ("Screenshot"), which would otherwise be read ahead of the new caption; the picture and every other byte stay as they were. JPEG files are written by editing their segments (#81): only the XMP segment is replaced (with about 2 KB of padding, other apps' XMP kept), plus, when the caption changes, IFD0's ImageDescription taken out in place within the EXIF, which keeps its size and offsets, since ImageIO reads it ahead of the XMP whatever it holds (Windows empties it only when it held the old caption, and also empties XPTitle). The EXIF thumbnail and MakerNote, comments, Photoshop's IPTC, the picture and a motion photo's video stay byte for byte. The IPTC caption isn't changed on either side: while its digest matches, the XMP's caption is the one read, and when it doesn't the Mac refuses the caption (it wouldn't read back). Both refuse Extended XMP and XMP that isn't valid UTF-8 or XML, and both replace a caption held in one language with no x-default there. Multi-picture JPEGs (Ultra HDR, MPO) are still refused on the Mac (#90). GIF, WebP, RAW and other formats are skipped and named. Get Info shows "Alt text in the file" and "Extended description in the file", and the Description panel shows the alt text. Windows writes the same two fields into JPEG, PNG and TIFF files (#62, #82). JPEGs are changed segment by segment, as the Mac's #81 does: only the XMP is replaced, keeping EXIF (thumbnail, MakerNote), comments, the picture and a motion photo's video byte for byte (EXIF's own title is emptied in place when it held the old caption), and ratings go in the XMP with EXIF's rating patched in place (#86). Multi-picture JPEGs (Ultra HDR, MPO) are changed only when that keeps their size. TIFFs go through WIC. Its automatic saving leaves another app's extended description alone. PNGs are changed chunk by chunk, as the Mac's #61 does: only the XMP chunk is replaced, and Windows keeps a PNG's Title in that XMP, so it follows the caption, and ratings go in that XMP too; when the caption changes, the eXIf description (a screenshot's "Screenshot") is emptied in place, as the Mac removes it (#82). HEIC keeps a Title-only caption on Windows, since WIC can't write HEIC's metadata. Windows' Get Info shows "Alt Text in the File". The Photos library has no such fields, so on the Mac its photos keep a caption only.

## Describing in the background

- **Windows:** Photo > Describe Photos in the Background. The library's photos not described yet (added folders, network shares and the Pictures library) are described behind the scenes, newest first: when it's turned on, at each start, and for a folder as it's added, with "X of Y" in the status bar (#96).
- **Mac:** Photo > Describe Photos in the Background (macOS 27), the same as Windows since #102. Every photo not described yet (the Photos library newest first, and the added folders' photos) is described behind the scenes: when it's turned on and at each launch, so a big library carries on across restarts. A folder just added, and photos new since the last scan, go ahead of the backlog. "X of Y" is in the status bar; it waits on Low Power Mode and while the Mac is hot; when Apple Intelligence is busy (it limits apps that aren't in front) it waits and tries the same photo again; and five failures in a row stop the run, with the reason in the status bar. Photos only in iCloud aren't downloaded for it. Only descriptions are saved; nothing goes into the files unless Save Descriptions in Photos is on (and not while read-only). Differences: the Mac doesn't announce each folder's finish, and speaks only while Photo Finder is in front.

## Now the same on both

- **Adding folders:** File > Add Folder to Library… and Remove Folder from Library on both, and Delete on an added folder in the sidebar removes it after asking (a folder inside one says it's part of it). Both say "Added Pictures" and "Removed Pictures from Photo Finder". Added folders are listed under Folders in the sidebar, with the subfolders that hold photos, and their photos are described (automatically, Describe Photo, Describe Again, Get Info) and their descriptions saved by file path, size and modified time. Differences: the Mac's default library is Photos, which can't be removed, while Windows can remove Pictures library folders; the Mac lists an added folder even when it's empty or its disk isn't connected, so it can still be removed. The Mac reads Date Taken, dimensions, caption, keywords, rating and location from the file with ImageIO.
- **Columns dialog:** View > Columns… on both, with the same lists, buttons, keys (Alt on Windows, Option on the Mac) and announcements. Column order sets the order each row is read in.
- **Saved descriptions:** both save descriptions, so a photo is described once.
- **Describe Photos Automatically:** Photo > Describe Photos Automatically on both, on by default. The photo you arrow to in the list or gallery is described after a short pause (700 ms) and the description is spoken behind other speech, only while you're still on that photo. Saved descriptions are spoken the same way.
- **Describe Again:** Photo > Describe Again on both (Shift-Option-Command-D on the Mac, Ctrl+Alt+Shift+D on Windows, where it's also in Preview) describes the photo you're on afresh, says "Describing *name* again" and replaces its saved description; Get Info's button says Describe Again once a description is saved. Automatic describing leaves the photo alone meanwhile. On Windows the shortcut does nothing while you're typing, because Ctrl+Alt is AltGr on many keyboards.
- **The gallery shows the description:** under the photo, with its name, kind, date and caption, on both. The image itself is named just for the photo.
- **Search result count:** both say "No results", "1 result" or "12 results" once typing in Search pauses.
- **View > Sort By:** both sort by any column without its header, with a checkmark on the current one. Choosing it again reverses it, and both say "Sorted by Date Taken, descending".
- **Gallery Home and End:** both go to the first and last item.
- **Help > Check System…:** on both, one line per check, OK or what to do, with Check Again, Copy to Clipboard and Report a Bug. The Mac checks macOS, Apple silicon, Apple Intelligence and Photos access; Windows checks the Windows build, the NPU, Windows AI (model and helper) and the library folders. Both list the version and the describing settings; the Mac's Saved descriptions line says how much of the library is described ("39% described, 159 of 400 photos", counting the Photos library and added folders, videos aside). After the checks, both show the details behind the AI (#94), one line each, in the same order where the facts match: memory, power, this session's description timings (count, typical, slowest, each photo counted once), the last three failures, and Check AI Description's last result. Windows also shows Windows' edition, the processor, the NPU's driver, the AI helper's version, the Windows App Runtime and Windows AI packages, and text recognition's and Phi Silica's states. The Mac's macOS line has the build and its Processor line names the chip; its power line is Low Power Mode and the thermal state, and it adds Apple Intelligence's model state and language. Both reports leave folder paths out.
- **Help > Report a Bug…:** on both, a new GitHub issue opens with the questions and the system check filled in (titled [Mac] or [Windows]), and the same text is copied. Both leave folder paths out of the report. Both move to the app kit's relay later (#33).
- **Help > Check AI Description… (#95):** on both. It describes a sample picture drawn for the app (a red mug on a wooden table beside a sign reading OPEN, `windows/src/PhotoFinder/Assets/SamplePhoto.jpg`, which the Mac shares) with the description type or prompt in use. It shows the description first, so focus reads it, then whether it mentions the mug, the table and the sign, the time and what answered. It saves nothing, and its result goes in Check System and Report a Bug. Both say "Describing the sample photo" as it starts and the summary after, and say why without trying when the AI isn't available. Windows names the description type and the AI helper's version; the Mac names the prompt (standard or your own) and the macOS the model came with. On Windows it shares the Check System window; on the Mac it has its own, laid out the same, which Escape closes.
- **User guide and privacy policy (#105):** `docs/user-guide.md` and `docs/PRIVACY.md` cover both apps. The Mac's Help menu opens them (User Guide, Privacy Policy); Windows to add the same two items.
- **Diagnostic log (#98, #103):** both keep one file a day in the data folder's Logs folder (`~/Library/Application Support/PhotoFinder/Logs` on the Mac), kept two weeks, with Help > Open Log Folder: what the app started with, and what went wrong (the AI, describing, background describing, saving, crashes; the Mac logs Objective-C exceptions nothing caught off the main thread; Swift crashes go to macOS's own crash reports). The home folder is written as ~ (%USERPROFILE% on Windows); file names stay, so bug reports say to look before attaching it. The Mac also sends each line to the unified log, so Console shows it.
- **Help menu order:** Windows has the order agreed in #13: Check for Updates…, Report a Bug…, Check System…, Check AI Description…, Open Log Folder, separator, About. The Mac's Help menu has Check for Updates…, Report a Bug…, Check System…, Check AI Description…, Open Log Folder, separator, User Guide, Privacy Policy, with About in the app menu as Mac apps do.
- **Saving descriptions in photos:** both have Photo > Use Description as Caption (asks before replacing anything) and one switch, **Photo > Save Descriptions in Photos**, off until the person agrees once, which fills empty captions and, in files, empty alt text, and never replaces what a person or another app wrote. A file's caption is `dc:description`, with `dc:title` kept in step when it's empty or was the caption. Windows matches (#62): the same switch and question in the Photo menu, `dc:description` in JPEG, PNG and TIFF files with Explorer's Title (`System.Title`) kept in step, and the old three-way setting carried over.
- **Description panel (#50):** View > Show Description on both, on by default (Option-Command-I on the Mac, Ctrl+Shift+I on Windows, since Ctrl+Alt is AltGr on many keyboards): the description in an editable box (corrections are saved and marked "Edited by you", and nothing replaces them without asking), a status line ("Describing…", "Saved description", "Edited by you", "Not described yet"), Describe Again / Use as Caption / Copy, and the caption with Edit Caption, in the F6 cycle after the list or gallery. Plus a Description column in View > Columns, off by default. On Windows, Enter saves a correction and Shift+Enter starts a new line; the panel's width is remembered.
- **Describing ahead:** stepping through photos one at a time with Describe Photos Automatically on, both apps describe the next photo in the direction you're going while the current description is read, so it's ready when you arrive. One photo ahead, only after you've settled, never spoken, dropped at once if you land elsewhere, no iCloud or OneDrive downloads, and not in the background. The Mac also waits on Low Power Mode or when running hot; Windows waits on energy saver, but has no app-level way to tell it's running hot, so it doesn't check that (#64). On Windows, work dropped after the photo has gone to Windows AI finishes and is saved, since stopping it would mean reloading the model.
- **Installing and updates:** Windows installs from a signed MSIX through App Installer, which updates it. The Mac is a signed, notarized disk image from GitHub releases tagged `mac-v<version>` (`scripts/release-mac.sh`, built on a Mac with Xcode 27). Both follow the apps' shared update experience (The-Idea-Place-Projects#12): Help's item reads "Check for Updates (running 0.1.0)…", both check quietly once a day and the item becomes "Update to 0.2.0 available…" when there is one, and the first launch after an update says "Photo Finder Update Installed" with See What's New. On the Mac choosing the item opens the download; on Windows it installs the update through App Installer (#85). Windows releases are to be tagged `windows-v<version>`, which See what's new links to (the releases list for a build of the same version); none exists yet. The spec's setting to turn the note off isn't on either app.
- **Read-only (#83, #84):** both start read-only at every launch. File > Read-Only Mode asks "Let Photo Finder change your photos?" (Keep Read-Only Mode is the default) before allowing changes until the app quits. The title ends "- Read-Only Mode" or "- Editing Mode" ("Mode", so a screen reader doesn't sound as if a control is read-only; Kelly, 13 Oct; Windows to match), and the writers themselves refuse while read-only.
- **The status bar from anywhere:** Control-F9 reads it and Control-Shift-F9 goes to it (Ctrl+F9 and Ctrl+Shift+F9 on Windows). On the Mac they're in the Go menu, with Next Pane and Previous Pane (Kelly, 13 Oct); on Windows, in the View menu. On Mac laptops, add Fn unless the function keys are set as standard keys.
- **Describe Photo:** Command-D on the Mac (list and gallery) and, to match, Ctrl+D on Windows (Ctrl+Shift+D until it changes), describing the photo you're on and speaking it (Kelly, 13 Oct). Shift with it goes to the Description panel's text and, pressed there, back to the list or gallery: Go > Go to Description or Back to Photos (Shift-Command-D) on the Mac; Ctrl+Shift+D on Windows to match.
- **Choosing how photos are described:** Windows has Photo > Description Type, with Windows AI's four kinds (Accessible, Detailed, Brief, Diagram). The Mac's Settings has the prompt itself, since Apple Intelligence takes any prompt.

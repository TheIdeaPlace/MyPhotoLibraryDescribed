# Mac and Windows: what's different

My Photo Library Described has two separate apps: the Mac app (`PhotoFinder/`, SwiftUI and PhotoKit) and the Windows app (`windows/`, WPF). They aim at the same job, browsing photos like folders with a screen reader, but each is built on what its platform offers. This is the list of where they differ, so gaps can be closed on purpose. Update it when either app changes.

## Differences that come from the platform

These follow from what each operating system offers apps, and aren't gaps to close.

## Gaps to close

Each gap below has a GitHub issue with the `parity` label (`gh issue list --label parity`). Claim and coordinate there, as `CLAUDE.md` describes. When a gap is closed, move it to "Now the same on both" in the same PR.

### On the Mac, from Windows

- **Moving between panes.** Both have F6 and Shift+F6 (Go > Next Pane and Previous Pane on the Mac) for the sidebar, the list or gallery, search and the status bar, with Left and Right Arrow between status bar sections. On Windows the status bar is reached only with F6, not Tab, as in QuickMail; on the Mac, SwiftUI's focusable status sections may also be Tab stops.
- **Tests.** Both have tests (the Mac about 430, Windows about 300). Mac CI can't compile the macOS 27 code until GitHub's runners have Xcode 27.
- **Favorites and ratings in files in added folders.** Windows sets favorites (a five-star rating) and ratings in the files themselves. On the Mac, Toggle Favorite says it isn't available for files yet. Captions are written into files on the Mac too (#31).

### On Windows, from the Mac

- **Follow-up questions about a photo.** The Mac's Apple Intelligence answers follow-up questions after describing. Windows has them built (#24): Phi Silica answers in Get Info from the saved description and any text read from the photo. They stay hidden, because Phi Silica is a Limited Access Feature that Windows refuses an app without Microsoft's token, which Photo Finder doesn't have yet.
- **What's in the photo.** The Mac's Find Objects and Text lists objects and scenes (Vision's classifier) as well as reading text. Windows reads text only: Windows has no built-in classifier for apps.

## Describing in the background

- **Windows:** Photo > Describe Photos in the Background. The library's photos not described yet (added folders, network shares and the Pictures library) are described behind the scenes, newest first: when it's turned on, at each start, and for a folder as it's added, with "X of Y" in the status bar (#96).
- **Mac:** Photo > Describe Photos in the Background (macOS 27), the same as Windows since #102. Every photo not described yet (the Photos library newest first, and the added folders' photos) is described behind the scenes: when it's turned on and at each launch, so a big library carries on across restarts. A folder just added, and photos new since the last scan, go ahead of the backlog. "X of Y" is in the status bar; it waits on Low Power Mode and while the Mac is hot; when Apple Intelligence is busy (it limits apps that aren't in front) it waits and tries the same photo again; and five failures in a row stop the run, with the reason in the status bar. Photos Apple Intelligence's guardrails decline don't count towards the five, since that's a verdict on the photo. Photos it declines or can't read, and photos that fail while others in the same run are described, are skipped until they're edited or the app is updated (any new build); they're remembered in the data folder's BackgroundFailures.json. Windows does the same (#162, #163, #170), with two differences: a photo that can't be decoded is held like other failures, rather than remembered at once, since a missing HEIF codec on Windows gives that for every HEIC; and a timeout, or the AI helper stopping partway, is never remembered. Too much text in a photo counts as the photo's own verdict on Windows, as the content filter does. Photos only in iCloud aren't downloaded for it. Only descriptions are saved; nothing goes into the files unless Save Descriptions in Photos is on (and not while read-only). Differences: the Mac doesn't announce each folder's finish, and speaks only while My Photo Library Described is in front.

## Now the same on both

- **Accessibility fields in files (#31).** The Mac writes IPTC's Alt Text (Accessibility) and Extended Description (Accessibility) into JPEG, PNG, TIFF and HEIC files in added folders: alongside the caption, with Use Description as Caption (and the panel's Use as Caption) and with Save Descriptions in Photos (which only fills empty alt text). The alt text is the description when it's 250 characters or less, otherwise the whole sentences that fit; the extended description is the whole description, only when the alt text is shorter. PNG files are written by editing their chunks (#61): only the XMP changes, plus, when the caption changes, the EXIF description every screenshot carries ("Screenshot"), which would otherwise be read ahead of the new caption; the picture and every other byte stay as they were. JPEG files are written by editing their segments (#81): only the XMP segment is replaced (with about 2 KB of padding, other apps' XMP kept), plus, when the caption changes, IFD0's ImageDescription taken out in place within the EXIF, which keeps its size and offsets, since ImageIO reads it ahead of the XMP whatever it holds (Windows empties it only when it held the old caption, and also empties XPTitle). The EXIF thumbnail and MakerNote, comments, Photoshop's IPTC, the picture and a motion photo's video stay byte for byte. The IPTC caption isn't changed on either side: while its digest matches (or there's none), the XMP's caption is the one read, and when it doesn't, readers show the IPTC's, so both refuse to change the caption (#169), saying "An older caption saved in it by Photoshop or a similar app would still be read instead of the new one, so it was left as it is." The Mac finds it by reading the caption back through ImageIO; Windows, whose read-back takes the XMP, checks the digest itself (the MD5 of the IPTC block) (a digest of the wrong size counts as stale; Photoshop segments split to fit are joined first) and refuses when the IPTC holds a different caption. The alt text written with the caption is refused with it, on both, since it's one change; a rating set on its own still changes. Both show the IPTC caption that wins as the photo's caption, in Get Info and the list, so replacing it is asked about (Windows reads only the segment headers and Photoshop's segments for it, #181); a photo already cached on Windows shows its old caption until it's read again (a caption command reads it fresh, so the first one sets it right). Windows says the refusal before asking anything when every photo chosen would be refused, and Edit Caption says it instead of opening; the Mac finds out on the read-back, after asking. An empty IPTC caption shows the XMP's, on both. Both refuse XMP that isn't valid UTF-8 or XML, and both replace a caption held in one language with no x-default there. Both caption multi-picture JPEGs (Ultra HDR, Apple's HDR photos, MPO) the same way (#90): their Multi-Picture index is patched, the main picture's size grown by what the XMP added (and, were the XMP after the index, where the other pictures start), then checked to still point at a JPEG for each; a file with two indexes, or one that can't be followed, is refused only when the change would alter the file's size ("*name* holds a second picture, such as an HDR map, laid out in a way that can't be updated safely, so it was left as it is"). The gain map or other view stays byte for byte. Many Pixel photos (Ultra HDR, portrait) also carry Extended XMP, the rest of their XMP in further segments. Both caption them (#149, the Mac in #166): only the main XMP is replaced, keeping the `xmpNote:HasExtendedXMP` GUID that names the extension, and every Extended XMP segment stays byte for byte; first it checks the parts add up to one packet whose MD5 is that GUID, and refuses ("Its metadata is spread over several parts (Extended XMP) that don't add up") anything that doesn't, or an extension that holds a field being written. Windows checks the same (the GUID exact, in uppercase, each part non-empty, one main XMP), and also refuses when the extension holds a rating it would write (xmp:Rating or MicrosoftPhoto:Rating), since Windows writes ratings into the XMP. Both name the field in that refusal ("…and its caption is kept in another part"). GIF, WebP, RAW and other formats are skipped and named. Get Info shows "Alt text in the file" and "Extended description in the file", and the Description panel shows the alt text. Windows writes the same two fields into JPEG, PNG, TIFF and HEIC files (#62, #82, #31); it takes .heif and .hif files as HEIC too, where the Mac writes .heic only. JPEGs are changed segment by segment, as the Mac's #81 does: only the XMP is replaced, keeping EXIF (thumbnail, MakerNote), comments, the picture and a motion photo's video byte for byte (EXIF's own title is emptied in place when it held the old caption), and ratings go in the XMP with EXIF's rating patched in place (#86). Multi-picture JPEGs are captioned as on the Mac (#90). TIFFs go through WIC. Its automatic saving leaves another app's extended description alone. PNGs are changed chunk by chunk, as the Mac's #61 does: only the XMP chunk is replaced, and Windows keeps a PNG's Title in that XMP, so it follows the caption, and ratings go in that XMP too; when the caption changes, the eXIf description (a screenshot's "Screenshot") is emptied in place, as the Mac removes it (#82). HEICs are changed box by box (#31): the caption, Title, accessibility fields and rating go in an XMP item for the photo. An iPhone's HEIC has an XMP item already, but it describes the HDR gain map, so it's left alone and one is added for the photo, the way Windows' own property handler adds one (which Explorer then reads the Title and rating from). The pictures, EXIF, gain map and depth map stay byte for byte: when the meta box grows, only the places of the items after it change; a later change fits in the new XMP's padding, and one that doesn't moves the XMP to the end of the file with the old copy blanked. The EXIF item's description and title are emptied in place when the caption changes, as the Mac does for JPEG, since Windows' property handler (which saved HEIC captions as a Title before, rewriting the whole file) put the old caption there too and ImageIO reads it first. Every change is read back before it's saved: each other item must hold exactly the bytes it held. Windows' Get Info shows "Alt Text in the File". The Photos library has no such fields, so on the Mac its photos keep a caption only.
- **Adding folders:** File > Add Folder to Library… and Remove Folder from Library on both, and Delete on an added folder in the sidebar removes it after asking (a folder inside one says it's part of it). Both say "Added Pictures" and "Removed Pictures from My Photo Library Described". Added folders are listed under Folders in the sidebar, with the subfolders that hold photos, and their photos are described (automatically, Describe Photo, Redescribe, Get Info) and their descriptions saved by file path, size and modified time. Differences: the Mac's default library is Photos, which can't be removed, while Windows can remove Pictures library folders; the Mac lists an added folder even when it's empty or its disk isn't connected, so it can still be removed. The Mac reads Date Taken, dimensions, caption, keywords, rating and location from the file with ImageIO.
- **View > Labels… (#38, #140):** on both, it was Columns…. Two parts (tabs on Windows; on the Mac a List/Gallery choice at the top, which VoiceOver reads as radio buttons, since a SwiftUI tab view kept Tab from reaching Cancel and OK, #151) with the same Available and Shown lists, buttons, keys (Alt on Windows, Option on the Mac), announcements and a preview: List (the columns; their order sets the order each row is read in) and Gallery, which chooses what's said, in order, when you move to a photo in the gallery. The gallery items are Position ("12 of 400"), Name, Kind, Date Taken, Dimensions, Caption, Keywords, Rating and Place Taken; the default is Position only, and the description follows after the usual pause. The last label can't be removed. The move announcement and the image's own name are both the chosen items, so nothing is said twice (on Windows the image's name is updated without raising a name change on every move, so the move's announcement is said once). Enter in Shown presses OK on Windows; on the Mac Return there removes the item. Arrowing in the list is unchanged. Each part's explanation ("Choose which columns…") is said differently: on the Mac it's the lists' hint, which VoiceOver reads once after a pause; on Windows it's said once as the dialog opens and on changing tab (#155), since JAWS read a list's help text again with every item.
- **Saved descriptions:** both save descriptions, so a photo is described once, each with where it came from (#199, the Mac in #201, Windows in #203), in the same format and field names: Descriptions.json is `{"version": 2, "descriptions": {key: record}}`, each record `text`, `source` (`apple-intelligence` or `windows-ai`, or `person` once written or corrected in the Description panel, which is the "Edited by you" mark), `prompt`, `model`, `locale`, `os`, `app`, `created`, `durationMs`, and for a correction `edited` and `original` (the AI's text before the first correction). A field that isn't known is left out, and fields a reader doesn't know are ignored. EditedDescriptions.json is gone, and the old flat form isn't read, since nothing was released before it (Kelly, 14 Oct): such a file is set aside like any file that can't be read. Each platform fills the fields its own way: the Mac's `prompt` is the prompt's text and Windows' is the description type (`accessible`, `brief`, `detailed`, `diagram`); the Mac's `model` is FoundationModels' variant ("AFM 3 Core") and Windows', which names no model, is "Windows AI image description" with the version of Windows' AI components; `locale` is `en_US` on the Mac and `en-US` on Windows; `app` is "0.2.0 (12)" on the Mac and the package version ("0.2.0.1180") on Windows. Windows' `durationMs` is Windows AI's own time for the describing, not the wait for it; the first description after the helper starts also includes loading the model. Keys keep each platform's form. A file Windows can't read is moved aside as Descriptions.unreadable-*date*.json, as on the Mac, and one with a record it can't read in full keeps the other records, that record's text when it has one, and a copy of the file.
- **Describe Photos Automatically:** Photo > Describe Photos Automatically on both, on by default. The photo you arrow to in the list or gallery is described after a short pause (700 ms) and the description is spoken behind other speech, only while you're still on that photo. Saved descriptions are spoken the same way.
- **Redescribe (was Describe Again):** Photo > Redescribe on both, Command-R on the Mac and Ctrl+R on Windows, also in Preview (Kelly, 13 Oct; the Mac's Refresh moved to Shift-Command-R, and Windows' stays F5), describes the photo you're on afresh, says "Redescribing *name*" and replaces its saved description; Get Info's and the Description panel's button says Redescribe once a description is saved. Automatic describing leaves the photo alone meanwhile.
- **The gallery shows the description:** under the photo, with its name, kind, date and caption, on both. The image itself is named with the gallery's labels (#38).
- **Search result count:** both say "No results", "1 result" or "12 results" once typing in Search pauses. On both, rows a search hides leave the selection, so nothing out of sight is acted on.
- **View > Sort By:** both sort by any column without its header, with a checkmark on the current one. Choosing it again reverses it, and both say "Sorted by Date Taken, descending". Both keep folders ahead of photos in either direction, as File Explorer does, and break ties A to Z by name (Kelly, 13 Oct).
- **Gallery Home and End:** both go to the first and last item.
- **Help > Check System…:** on both, one line per check, OK or what to do, with Check Again, Copy to Clipboard and Report a Bug. The Mac checks macOS, Apple silicon, Apple Intelligence and Photos access; Windows checks the Windows build, the NPU, Windows AI (model and helper) and the library folders. Both list the version and the describing settings; both apps' Saved descriptions line says how much of the library is described ("39% described, 159 of 400 photos", rounded down, videos aside; the Mac counts the Photos library and added folders, and Windows counts descriptions of the Description Type in use). After the checks, both show the details behind the AI (#94), one line each, in the same order where the facts match: memory, power, this session's description timings (count, typical, slowest, each photo counted once), the last three failures, and Check AI Description's last result. Windows also shows Windows' edition, the processor, the NPU's driver, the AI helper's version, the Windows App Runtime and Windows AI packages, and text recognition's and Phi Silica's states. The Mac's macOS line has the build and its Processor line names the chip; its power line is Low Power Mode and the thermal state, and it adds Apple Intelligence's model state and language. Both reports leave folder paths out.
- **Help > Report a Bug… (#33, #138):** both have the app kit's form: Bug or Suggestion, Title (focus starts there), What happened, What you expected and Steps (or Suggestion), an optional Contact said to be public, "Include the system check" (on), a preview of exactly what's sent, and Send and Cancel. Send posts `{title, body, contact?, kind}` to the app kit's relay (app id `photofinder`) and says "Report filed as issue #N", with Open Issue; when the relay fails, or the build has no relay key, it offers the prefilled GitHub page (Open in Browser) and copies the report. Only a release build has the key: the Mac's reads it from `~/.signing-kit`, and Windows' build script copies it into the package as `appkit-relay.key`, from `~/.signing-kit` or the `APPKIT_RELAY_KEY` secret in CI. Check System's and Check AI Description's Report a Bug… open the form, Check AI Description's with its result. Both title reports [Mac] or [Windows] and leave folder paths out. While a report is on its way, both say "Still sending" rather than close (the relay answers within 15 seconds); the Mac's window's close button still closes it, and the report is filed regardless.
- **Crash reports (#33, #138):** both write a flag in the data folder at launch and remove it on a normal quit; when it's still there at the next launch, they ask once "My Photo Library Described quit unexpectedly last time. Report it?", and Report… opens the form with the end of the log, with the user folder written as ~ or %USERPROFILE%. The Mac takes the last 40 lines of the crashed run's log (and today's, when that's another day), and a summary of macOS's newest crash report for the app: the versions, the exception and the crashed thread's first 20 steps, without the Mac's identifiers. Windows has no crash report of its own to add (its log records unhandled exceptions), so it takes the last 40 lines of the newest log, read at start before the new run writes to it; it doesn't ask on the first start after an update, or when the flag's process is a copy still running. The Mac doesn't ask after the Mac was restarted or shut down with the app open, unless macOS recorded a crash first (#146); Windows closes the app normally when it restarts, so its flag is removed then. The question's default button differs: Not Now on Windows, as all its questions default to the safe answer (`QuestionDialog.AskSafely`), and Report… on the Mac. Both cut a log line at 1,500 characters and keep a report within the relay's 8,000 characters (7,800), dropping an attachment's oldest lines first after "(Earlier lines left out.)", so the preview is what's filed (#147). When not even a line fits, the Mac says "(Left out: the report is too long to include it.)" only if that note fits too; Windows adds the note regardless (#154).
- **About:** both have the version, a line on what the app is for, and links to the source code, the user guide and the privacy policy (#33, #138): the Mac's About panel is in the app menu, and Windows' is a window from Help > About.
- **Help > Check AI Description… (#95):** on both. It describes a sample picture drawn for the app (a red mug on a wooden table beside a sign reading OPEN, `windows/src/PhotoFinder/Assets/SamplePhoto.jpg`, which the Mac shares) with the description type or prompt in use. It shows the description first, so focus reads it, then whether it mentions the mug, the table and the sign (both take table, tabletop, desk, surface, counter or countertop for the table, since Apple Intelligence calls it "a wooden surface"), the time and what answered. It saves nothing, and its result goes in Check System and Report a Bug. Both say "Describing the sample photo" as it starts and the summary after, and say why without trying when the AI isn't available. Windows names the description type and the AI helper's version; the Mac names the prompt (standard or your own) and the macOS the model came with. On Windows it shares the Check System window; on the Mac it has its own, laid out the same, which Escape closes.
- **User guide and privacy policy (#105):** `docs/user-guide.md` and `docs/PRIVACY.md` cover both apps. Both apps' Help menus open them (User Guide, Privacy Policy).
- **Diagnostic log (#98, #103):** both keep one file a day in the data folder's Logs folder (`~/Library/Application Support/My Photo Library Described/Logs` on the Mac), kept two weeks, with Help > Open Log Folder: what the app started with, and what went wrong (the AI, describing, background describing, saving, crashes; the Mac logs Objective-C exceptions nothing caught off the main thread; Swift crashes go to macOS's own crash reports). The home folder is written as ~ (%USERPROFILE% on Windows); file names stay, so bug reports say to look before attaching it. The Mac also sends each line to the unified log, so Console shows it.
- **Help menu order:** Windows has the order agreed in #13: Check for Updates…, Report a Bug…, Check System…, Check AI Description…, Open Log Folder, separator, My Photo Library Described User Guide, Privacy Policy, separator, About. The Mac's Help menu has Check for Updates…, Report a Bug…, Check System…, Check AI Description…, Open Log Folder, separator, User Guide, Privacy Policy, with About in the app menu as Mac apps do.
- **Saving descriptions in photos:** both have Photo > Use Description as Caption (asks before replacing anything) and one switch, **Photo > Save Descriptions in Photos**, off until the person agrees once, which fills empty captions and, in files, empty alt text, and never replaces what a person or another app wrote. A file's caption is `dc:description`, with `dc:title` kept in step when it's empty or was the caption. Windows matches (#62): the same switch and question in the Photo menu, `dc:description` in JPEG, PNG, TIFF and HEIC files with Explorer's Title (`System.Title`) kept in step, and the old three-way setting carried over.
- **Next and previous photo from anywhere (#117, #119):** Go > Next Photo and Previous Photo, Command-Right and Command-Left on the Mac and Alt+Right and Alt+Left on Windows (Ctrl+arrows move by word in a text box). They step through photos in the list or gallery, past folders and videos, without moving focus, so you can stay in the Description panel's box (reading with a braille display, say) and the box follows. Each step says "*name*, *n* of *N*" (on Windows, only when focus isn't on the list, which says the row itself; in the gallery on both, the labels chosen in View > Labels…, #38, #145), or "No next photo" / "No previous photo" at the ends.
- **A preview of the photo in the Description panel, in list view (#120, #119):** on both, the photo you're on above its name, up to 240 high, hidden from screen readers, shrinking and then going in a short window, and not in the gallery. A placeholder holds its place while it loads, so what's below doesn't jump. Neither downloads: an iCloud-only or online-only OneDrive photo shows its thumbnail (on Windows, only one OneDrive already has), or the placeholder.
- **Description panel (#50):** View > Show Description on both, on by default (Option-Command-I on the Mac, Ctrl+Shift+I on Windows, since Ctrl+Alt is AltGr on many keyboards): the description in an editable box (corrections are saved and marked "Edited by you", and nothing replaces them without asking), a status line ("Describing…", "Saved description", "Edited by you", "Not described yet"), Redescribe / Use as Caption / Copy, and the caption with Edit Caption, in the F6 cycle after the list or gallery. Plus a Description column in View > Labels, List tab, off by default. On Windows, Enter saves a correction and Shift+Enter starts a new line; the panel's width is remembered.
- **Describing ahead:** stepping through photos one at a time with Describe Photos Automatically on, both apps describe the next photo in the direction you're going while the current description is read, so it's ready when you arrive. One photo ahead, only after you've settled, never spoken, dropped at once if you land elsewhere, no iCloud or OneDrive downloads, and not in the background. The Mac also waits on Low Power Mode or when running hot; Windows waits on energy saver, but has no app-level way to tell it's running hot, so it doesn't check that (#64). On Windows, work dropped after the photo has gone to Windows AI finishes and is saved, since stopping it would mean reloading the model.
- **Installing and updates:** Windows installs from a signed MSIX through App Installer, which updates it. The Mac is a signed, notarized disk image. Both come from one GitHub release tagged `v<version>` (Kelly, 13 Oct): the tag builds and signs the Windows installer in CI, and `scripts/release-mac.sh` attaches the Mac's disk image, built on a Mac with Xcode 27. The Mac also reads its earlier `mac-v` tags. Both follow the apps' shared update experience (The-Idea-Place-Projects#12): Help's item reads "Check for Updates (running 0.2.0)…", both check quietly once a day and the item becomes "Update to 0.3.0 available…" when there is one, and the first launch after an update says "My Photo Library Described Update Installed" with See What's New. On the Mac choosing the item opens the download; on Windows it installs the update through App Installer (#85). See what's new links to the `v<version>` release on both (on Windows, the releases list for a build of the same version). The spec's setting to turn the note off isn't on either app.
- **Read-only (#83, #84):** both start read-only at every launch. File > Read-Only Mode asks "Let My Photo Library Described change your photos?" (Keep Read-Only Mode is the default) before allowing changes until the app quits. The title ends "- Read-Only Mode" or "- Editing Mode" ("Mode", so a screen reader doesn't sound as if a control is read-only; Kelly, 13 Oct), and the writers themselves refuse while read-only.
- **The status bar from anywhere:** Control-F9 reads it and Control-Shift-F9 goes to it (Ctrl+F9 and Ctrl+Shift+F9 on Windows). On the Mac they're in the Go menu, with Next Pane and Previous Pane (Kelly, 13 Oct); on Windows, in the View menu. On Mac laptops, add Fn unless the function keys are set as standard keys.
- **Describe Photo:** Command-D on the Mac (list and gallery) and, to match, Ctrl+D on Windows, describing the photo you're on and speaking it (Kelly, 13 Oct). Shift with it goes to the Description panel's text and, pressed there, back to the list or gallery: Go > Go to Description or Back to Photos, Shift-Command-D on the Mac and Ctrl+Shift+D on Windows.
- **Choosing how photos are described:** Windows has Photo > Description Type, with Windows AI's four kinds (Accessible, Detailed, Brief, Diagram). The Mac's Settings has the prompt itself, since Apple Intelligence takes any prompt.
- **Edit > Copy Description (#175, #176, #178):** on both, Shift-Command-C / Ctrl+Shift+C and in the photo's context menu, with the same words: the photo you're on in the gallery, or the photos selected in the list, in the list's order, each under its name when there's more than one; a correction in the Description panel not saved yet is copied as typed, without saving it. Windows also has no context menu in the gallery, so there it's Edit > Copy Description or Ctrl+Shift+C.
